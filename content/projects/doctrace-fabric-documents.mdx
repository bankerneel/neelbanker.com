## Problem

Diplomas, licences, permits and inspection reports flow from an issuer to a holder, then have to be trusted by someone who was never part of that exchange. A PDF with a signature image is as easy to forge as paper, and the only real check is calling the issuer, which almost nobody does.

## Approach

Stop protecting the file and remove it. Each record exists as structured data inside a permissioned Hyperledger Fabric network; a PDF, image or QR code is only a rendering of that data. There is no canonical file to intercept, alter or forward.

## Architecture

- Private channels and a certificate authority per organisation, so universities, agencies and enterprises share one network without handing identity control to a shared operator
- Attribute-based access control (ABAC) in chaincode plus ACLs on channel resources, backed by per-record key pairs, so access is decided per record rather than per organisation
- Parent–child record nodes in chaincode for version history: a correction attaches to its predecessor and marks it obsolete, nothing is overwritten, and the app always resolves one current version
- Receiver-controlled sharing: the holder shares with named people or a revocable public link, and a guest can verify a record without an account
- Attachments stored in IPFS, with only the content identifier written on-chain
- CouchDB world state for rich queries; Node.js APIs, including a public issuance and verification API

## Outcome

- DocTrace became an authorised Texas DIR vendor and won a CIO Review award
- Anyone can verify a record without an account and without contacting the issuer
- Corrections keep the full amendment history while the app always shows one current version

## Lessons

Immutability and correctness are different things. An append-only ledger has no native "current version", so version lineage has to be modelled in chaincode, not assumed. And Fabric only pays off when you design for the network: who has to agree, and who is allowed to see what.
